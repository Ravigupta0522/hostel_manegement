# DESIGN SYSTEM

---

## 4.1 Design Principles

The Hostel Management System must follow a simple, clean, professional, and consistent design system across the entire application.

### Simplicity

- Keep the interface simple and easy to understand.
- Avoid unnecessary visual elements.
- Each screen should focus on its primary purpose.
- Avoid excessive decoration and visual complexity.

### Clean UI

- Use clean layouts with proper spacing and alignment.
- Maintain sufficient whitespace between sections and components.
- Avoid overcrowded screens.
- Content should remain easy to scan and understand.

### Professional Appearance

- The overall design should look professional and suitable for a hostel management application.
- Use a consistent visual language across Student and Admin interfaces.
- Avoid unnecessary gradients, excessive shadows, glassmorphism, 3D effects, or decorative animations.

### Consistency

- Buttons, cards, input fields, typography, spacing, icons, and other UI elements must follow consistent styles.
- The same type of action should use the same visual pattern throughout the application.
- Student and Admin screens should maintain the same overall design system while keeping their interfaces separate.

### Responsive Design

- The design must adapt to mobile, tablet, and desktop screen sizes.
- Mobile layouts should prioritize touch interaction and readable content.
- Desktop layouts should use the available screen width effectively.
- Components must remain visually consistent across different screen sizes.

---

## 4.2 Color Palette

The application should use a minimal and professional color palette.

### Primary Color

- **Dark Blue / Slate Blue**
- Used for primary actions, important navigation elements, selected states, and key interface elements.

### Background Colors

- **White** → Main application background.
- **Light Gray** → Secondary sections, containers, or subtle backgrounds.

### Text Colors

- **Dark Charcoal / Near Black** → Primary text.
- **Medium Gray** → Secondary text and supporting information.
- **Light Gray** → Less prominent text where required.

### Status Colors

Use status colors only where necessary to communicate a clear state.

- **Success** → Green
- **Warning** → Orange/Amber
- **Error** → Red
- **Information** → Blue

### Color Usage Rules

- Keep the number of colors limited.
- Do not use excessive colors on a single screen.
- Avoid unnecessary gradients.
- Avoid bright or highly saturated colors as primary visual elements.
- Status colors should be used consistently throughout the application.

---

## 4.3 Typography

Typography must be clean, readable, and consistent throughout the application.

### Font

Use a modern, clean, and highly readable sans-serif font throughout the application.

### Typography Hierarchy

The application should maintain a clear hierarchy between:

- Page titles
- Section headings
- Sub-headings
- Body text
- Supporting text
- Labels
- Buttons
- Form fields
- Navigation text

### Typography Rules

- Page titles should have clear visual importance.
- Section headings should be distinguishable from body content.
- Body text must remain comfortable to read on both mobile and desktop.
- Supporting text should use a smaller and lighter visual treatment.
- Button and navigation text should remain clearly readable.
- Avoid using too many font sizes or font weights.
- Maintain consistent typography across Student and Admin interfaces.

---

## 4.4 UI Components

All reusable UI components must follow the defined design system and maintain consistent appearance throughout the application.

### Buttons

- Primary Button
- Secondary Button
- Text Button
- Icon Button
- Destructive/Action Button

Buttons must have consistent:

- Height
- Padding
- Border radius
- Typography
- Icon alignment
- Interaction states

### Input Components

- Text Field
- Password Field
- Search Field
- Dropdown
- Date Picker Field
- Number Input
- Multiline Text Field

Input fields should provide clear labels, readable text, appropriate spacing, and validation/error states where required.

### Cards

Cards should be used to group related information.

Card design should maintain:

- Consistent padding
- Consistent border radius
- Clear content hierarchy
- Subtle borders or shadows where required
- Consistent spacing between cards

### Navigation Components

- App Bar
- Bottom Navigation
- Navigation Rail
- Desktop Sidebar
- Tab Navigation
- Breadcrumbs where required

Navigation components must remain consistent with the responsive layout of the application.

### Dialogs and Bottom Sheets

- Confirmation Dialog
- Information Dialog
- Action Dialog
- Form Dialog
- Bottom Sheet

Dialogs and bottom sheets should clearly communicate their purpose and provide appropriate actions.

### Lists

- Standard List
- List Item
- Sectioned List
- Searchable List
- Filterable List

Lists should maintain consistent spacing, alignment, and interaction patterns.

### Status Components

- Status Badge
- Status Chip
- Progress Indicator
- Empty State
- Loading State
- Error State

Status components should use the defined status colors consistently.

### Feedback Components

- Snackbar
- Toast/Message
- Success Message
- Error Message
- Warning Message

Feedback should clearly communicate the result of a user action without unnecessary visual interruption.

### Data Components

- Data Table
- Summary Card
- Statistic Card
- Filter Bar
- Search Bar
- Pagination where required

These components should be designed to remain readable and usable on both desktop and smaller screens.

### Icons

- Use a consistent icon style throughout the application.
- Icons must have clear meaning and should support the associated text/action.
- Avoid unnecessary decorative icons.
- Maintain consistent icon sizing and alignment.

### Component Consistency

All UI components must:

- Follow the same color palette.
- Follow the same typography system.
- Maintain consistent spacing and sizing.
- Use consistent border radius.
- Maintain consistent interaction states.
- Work appropriately across mobile, tablet, and desktop layouts.
